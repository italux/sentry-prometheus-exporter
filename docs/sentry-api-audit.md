# Sentry API Audit

This document tracks findings from auditing the Sentry API endpoints used by the sentry-prometheus-exporter, as described in issue #114. See https://docs.sentry.io/api/ for the full API documentation.

| SentryAPI method | Endpoint (as called today) | Docs page checked | Verdict | Action | Env var |
|---|---|---|---|---|---|
| `organizations()` | `GET organizations/` | https://docs.sentry.io/api/users/list-your-organizations/ (linked from index https://docs.sentry.io/api/organizations/) | Current — docs show `GET /api/0/organizations/` with no deprecation notice; the endpoint moved documentation location (now filed under "Users") but the path is unchanged. | None | |
| `projects(org_slug)` | `GET organizations/{org}/projects/?all_projects=1` | https://docs.sentry.io/api/organizations/list-an-organizations-projects/ | Current — documented path is `GET /api/0/organizations/{organization_id_or_slug}/projects/`, matching what's called today. The `all_projects=1` query param is not documented (only `cursor`, `per_page`, `query` are listed) but is not flagged deprecated or rejected; treat as an undocumented/legacy passthrough param, not a broken endpoint. | None (query param not in current docs; monitor) | |
| `get_project(org_slug, project_slug)` | `GET projects/{org}/{proj_slug}/` | https://docs.sentry.io/api/projects/retrieve-a-project/ | Current — documented path is `GET /api/0/projects/{organization_id_or_slug}/{project_id_or_slug}/`, matching what's called today (slugs are accepted values for both path segments). No deprecation notice. | None | |
| `project_stats(org_slug, project_slug)` | `GET projects/{org}/{proj_slug}/stats/?stat={stat}&since={since}&until={until}` (called once per stat name: `received`, `rejected`, `blacklisted`) | https://docs.sentry.io/api/projects/retrieve-event-counts-for-a-project/ | Current — documented path is `GET /api/0/projects/{organization_id_or_slug}/{project_id_or_slug}/stats/` with `stat`, `since`, `until` query params, matching what's called today. `received`, `rejected`, `blacklisted` are all documented valid `stat` values (docs also list a `generated` value, unused by this code). No deprecation notice. Date-math for `since`/`until` was already fixed by PR #53 and was out of scope here. | None | |
| `issue_events(issue_id, environment=None)` | `GET issues/{issue_id}/events/` (with `environment` set: previously appended `&environment={env}&sort=date` with no leading `?`, producing a malformed URL like `issues/123/events/&environment=prod`) | https://docs.sentry.io/api/events/list-an-issues-events/ (path shown there is org-scoped: `GET /api/0/organizations/{organization_id_or_slug}/issues/{issue_id}/events/`; the exporter calls the shorter, non-org-scoped `issues/{issue_id}/events/` form, which still exists and works but isn't the path documented on this page) | Current, with a confirmed bug — no deprecation notice found for the `environment` query param (documented as `array(string)`, "The name of environments to filter by"), but the exporter's query-string construction was broken: when `environment` was passed, the code appended a bare `&environment=...` segment with no preceding `?`, so the parameter was silently glued onto the path instead of forming a valid query string. | **Fixed unconditionally** (not deprecation-related): changed the query-string prefix from `&` to `?` in `libs/sentry.py::issue_events` so the URL is now `issues/{issue_id}/events/?environment={env}&sort=date`. Pinned by `test_issue_events_with_environment_builds_valid_query_string` and `test_issue_events_without_environment_calls_expected_endpoint` in `tests/test_sentry_api_endpoints.py`. No `use_legacy_api` gating needed — this ships regardless of the docs findings. | |
| `issue_release(issue_id, environment=None)` (referred to as `current_release` in the audit brief; no method by that name exists — this is the actual method) | `GET issues/{issue_id}/current-release/` (optionally `?environment={env}`) | Checked https://docs.sentry.io/api/events/retrieve-the-current-release-for-an-issue/ (404 — page does not exist) and the full current endpoint listings at https://docs.sentry.io/api/events/ and https://docs.sentry.io/api/releases/ (no "current release for an issue" endpoint appears in either index). `GET /api/0/organizations/{organization_id_or_slug}/issues/{issue_id}/` (https://docs.sentry.io/api/events/retrieve-an-issue/) now returns a `currentRelease` field directly on the issue object. | Undocumented — this endpoint is absent from Sentry's current live API docs entirely (both the dedicated page and both relevant index pages). No explicit deprecation banner could be found (the page is simply gone, so no banner text is retrievable), so this is not a confirmed formal deprecation, but the functionality appears to have been folded into the `currentRelease` field on the "Retrieve an Issue" response instead of a standalone endpoint. The endpoint may still work as an unofficial/legacy path. | None (endpoint not in current docs; monitor). No code change made and no `use_legacy_api` gating added, since no explicit deprecation notice was found to migrate away from — flagging for follow-up rather than a blind behavioral migration. Added pin tests `test_issue_release_without_environment_calls_expected_endpoint` and `test_issue_release_with_environment_calls_expected_endpoint` to lock in current behavior so any future migration has a safety net. | |
| `environments(org_slug, project)` (brief sketched it as `environments(org_slug, proj_slug)` with a string; the actual method takes `project` — a project dict — and reads `project.get("slug")`) | `GET projects/{org}/{proj_slug}/environments/` | https://docs.sentry.io/api/environments/list-a-projects-environments/ (linked from the project-scoped side of https://docs.sentry.io/api/environments/) | Current — documented path is `GET /api/0/projects/{organization_id_or_slug}/{project_id_or_slug}/environments/`, matching what's called today. Documented query param is `visibility` (`all`\|`hidden`\|`visible`, defaults to `visible`), which the exporter does not pass (defaults to `visible`, a reasonable default). No deprecation notice present on the page. | None | |
| `issues(org_slug, project, environment=None, age="24h")` (brief sketched `issues(org_slug, proj_slug, query=..., stats_period=...)`; the actual method takes a project dict, no `query`/`stats_period` kwargs, and builds its own `query=age%3A-{age}` filter) | `GET projects/{org}/{proj_slug}/issues/?project={proj_id}&sort=date&query=age%3A-{age}` (optionally `&environment={env}`) | https://docs.sentry.io/api/events/list-a-projects-issues/ | **Confirmed deprecated.** The live docs page carries this banner directly under the endpoint's method/URL line: "Deprecated: This endpoint has been replaced with the Organization Issues endpoint which supports filtering on project and additional functionality." The replacement is `GET /api/0/organizations/{organization_id_or_slug}/issues/` (https://docs.sentry.io/api/events/list-an-organizations-issues/), which accepts the same `project` query param used today for filtering. This resolves the open question from PR review: as of this check, Sentry is actively steering callers away from the project-scoped listing. | **Migrated behind `use_legacy_api`** (default `True`, unchanged). Added `use_legacy_api` param to `SentryAPI.__init__`; when `True` (default) `issues()` keeps calling the exact legacy URL shown above, byte-for-byte identical to before this change — no breaking change. When `False`, it calls `GET organizations/{org}/issues/?project={proj_id}&sort=date&query=age%3A-{age}` instead. Pinned by `test_issues_calls_expected_endpoint` (legacy/default path) and `test_issues_with_legacy_api_disabled_calls_organization_scoped_endpoint` (new path) in `tests/test_sentry_api_endpoints.py`. | `use_legacy_api=True` (default) |
